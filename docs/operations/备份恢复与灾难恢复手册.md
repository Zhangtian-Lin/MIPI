# 备份恢复与灾难恢复手册

> 版本：v1.0-draft

## 1. 目标

在误删、错误迁移、服务故障、安全事件或区域故障后恢复 PostgreSQL、对象存储、契约、来源注册表和审计链。

## 2. 备份基线

- PostgreSQL：每日全量/基础备份并启用连续日志或等价时间点恢复；
- 对象存储：版本控制、生命周期和不可变保护按环境配置；
- 配置与契约：版本库保存；
- 密钥：由密钥管理系统备份，禁止写入普通备份；
- 搜索索引：视为可重建，不作为唯一事实源。

## 3. 初始目标

测试阶段目标 RPO 24 小时、RTO 8 小时；公开测试前根据业务价值收紧并批准。生产数据库建议支持更细粒度时间点恢复。

## 4. 恢复顺序

冻结写入 → 确定恢复点 → 恢复数据库 → 恢复/连接对象版本 → 校验引用和哈希 → 重放 Outbox → 重建搜索投影 → 冒烟测试 → 分阶段恢复流量。

## 5. 恢复校验

- 随机文档能回到原始对象；
- Claim 与 Evidence 引用完整；
- 审计日志连续；
- Published Projection 可从 L3 重建；
- 用户关注和权限一致；
- 未重复发送通知。

## 6. 演练

至少每季度在隔离环境恢复一次，记录耗时、失败点和实际 RPO/RTO。没有成功恢复演练的备份不能视为可靠。
