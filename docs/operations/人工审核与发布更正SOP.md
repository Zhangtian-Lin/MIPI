# 人工审核、发布与更正 SOP

> 版本：v1.1-draft

## 1. 角色

- Reviewer：核对原文、字段、实体和冲突；
- Senior Reviewer：处理政策、政治、重大金额和复杂冲突；
- Publisher：批准公开投影；
- Data Steward：批准实体合并、分类和历史更正；
- Security/Compliance：处理隔离内容、隐私和版权。

同一高风险内容的提取者不能成为唯一批准者。

## 2. 审核等级

| 风险 | 示例 | 要求 |
|---|---|---|
| R0 | 低风险已知格式 | 自动校验，可抽样 |
| R1 | 普通企业公告 | 一人审核 |
| R2 | 重大投资、政策条件、项目取消 | 一名 Reviewer + 一名 Senior Reviewer |
| R3 | 正式选举、争议指控、法律效力、敏感更正 | 双人审核并由 Publisher 批准 |

## 3. 审核清单

- 来源身份与 S 等级是否匹配；
- 原文版本、日期和 source span；
- 金额、币种、条件、否定和未来时态；
- 企业、项目、政策和地理实体是否正确；
- 是否为转载或同一 independence group；
- F 等级是否有足够依据；
- 冲突是否完整呈现；
- 是否涉及隐私、版权、诽谤或安全风险；
- 页面标题是否超出证据。

## 4. 发布决策

结果为 `approve`、`approve_with_limits`、`return_for_fix`、`reject`、`quarantine`。决定必须包含理由、审核人、时间和规则版本。

F0 默认不公开；F1 仅以明确“单一来源报道”展示；R2/R3 不允许全自动发布。

### 4.1 L2 采集接纳门槛

采集审核通过只表示该原始证据可以继续进入抽取、验证和 L3 建模，不等于 Publisher
批准公开。当前机器规则为：

| 风险 | 完成接纳所需的独立决定 |
|---|---|
| R0 / R1 | 一名 `reviewer` |
| R2 | 一名 `reviewer` + 一名不同人员的 `senior_reviewer` |
| R3 | 一名 `reviewer` + 一名 `senior_reviewer` + 一名 `publisher`，三者人员不同 |

同一人员不能通过切换角色为同一任务重复表决。`approve_with_limits` 必须列出限制条件；
任意角色选择 `quarantine` 会立即隔离任务。Security/Compliance 可以隔离，但不能代替编辑
审核作出通过、退回或拒绝决定。

每次决定分别写入 `review_decisions`，包含审核人、角色、决定、理由、规则版本、限制条件和
时间。最终状态更新、审计日志和 Outbox 事件与该决定在同一数据库事务中提交。

### 4.2 当前状态含义

- `in_review`：尚未满足风险等级要求的全部独立决定；
- `approved` / `approved_with_limits`：通过 L2 接纳门槛，文档仍为 `staged`；
- `returned`：退回采集或处理环节修正；
- `rejected`：不接受为后续情报输入，但保留原文和审计；
- `quarantined`：限制访问，不能通过普通审核按钮释放。

本地工作台允许用测试身份头验证流程；生产环境在接入真实身份提供方前必须拒绝审核写入。

## 5. 更正与撤回

发现错误后：冻结相关投影 → 确定受影响 Claim/Event/Page/Answer → 保存旧版本 → 发布更正 → 重新计算统计和搜索 → 通知受影响订阅 → 完成根因分析。

严重错误不得静默改字。页面显示更正时间、原错误性质和新证据。撤回不删除审计记录。

## 6. 时效

- 安全、隐私、错误选举结果：立即升级；
- 重大金额或政策错误：目标 4 小时内初步处置；
- 普通事实更正：目标 1 个工作日；
- 分类和别名问题：进入数据治理队列。

时效为运营目标，正式 SLA 需在上线前批准。
