# 监控告警与事故响应手册

> 版本：v1.0-draft

## 1. 可观测性

统一 `request_id`、`run_id`、`task_id`、`document_id`、`event_id` 和脱敏用户 ID。日志结构化并区分应用、安全、审计和访问日志。

## 2. 核心指标

- 来源成功率、最新成功时间和发布到采集延迟；
- 队列积压、任务耗时、重试和 dead letter；
- Schema 失败、解析/OCR/翻译失败；
- F 等级异常升级、冲突量和审核积压；
- API 成功率、P95 延迟和错误码；
- 页面可用性和构建版本；
- 数据库连接、存储、复制和备份；
- 模型延迟、Token、成本和拒绝率；
- 安全事件和越权尝试。

## 3. 初始服务目标

测试期先建立基线；公开测试前批准 SLO。建议起点：核心 API 月可用性 99.5%，高价值来源 24 小时内发现，严重错误更正目标 4 小时内初步处置。

## 4. 事故等级

- SEV1：数据泄漏、越权发布、错误正式选举结果、系统不可用；
- SEV2：大面积采集或 API 失败、错误政策状态、队列持续积压；
- SEV3：单来源解析失败、局部页面错误；
- SEV4：低风险数据质量和体验问题。

## 5. 响应流程

发现 → 确认 → 限制影响 → 保留证据 → 通知负责人 → 修复/回滚 → 验证 → 恢复 → 复盘。

SEV1 立即停止相关自动发布和吊销受影响凭证。事故期间不删除日志或历史版本。

## 6. 复盘

记录时间线、影响、检测缺口、根因、临时措施、永久措施、负责人和完成日期。重点改进系统，不以个人归责替代控制措施。
