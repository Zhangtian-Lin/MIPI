# 事件与证据首条闭环

> 版本：v1.0-draft  
> 状态：本地闭环实现

## 1. 目标

把已完成人工 L2 接纳的原文转换为私有事件、原子 Claim 和精确 source span；仅由
Publisher 创建不可覆盖的 L4 revision。公开 `/v1/changes` 最多返回十条当前 revision，
候选、隔离、私有 L3 和未发布事件不会进入网页。

## 2. 数据流与边界

```text
approved L2 原文
→ Processing Agent 选择精确字符范围并提交中文结构化结果
→ 服务端逐字符校验 quote_original 与保存原文一致
→ Event + Claim + ClaimEvidence（canonical_private / F1）
→ 服务端计算证据、范围与 F 等级阻塞项
→ Publisher 填写理由并确认
→ EventPublication L4 revision + Audit + Outbox
→ GET /v1/changes / GET /v1/events/{eventId}
```

Processing Agent 不能指定或提升 F 等级。通用事件首版固定从 F1 开始；来源 S 等级、
`verification_hint`、模型置信度和摘要流畅度都不能自动提升 F。F1 公开时必须显示单一来源
提示。后续 F2–F4 只能通过 Claim 级验证规则和独立证据扩展。

## 3. Source span

每项首版事件必须保存原文字符 `start/end`、原文片段、中文翻译、文档版本、来源、语言、
抓取时间、模型 ID 和 Prompt 版本。服务端从 PostgreSQL 保存的 `text_original` 校验片段，
不信任客户端重复提交的原文。片段限制为 500 字符，避免把长篇版权内容直接公开。

## 4. 发布与修订

- 投影与发布均使用幂等键和请求指纹；相同键的新输入返回冲突；
- Publisher、理由、规则版本、投影 JSON、Audit 和 Outbox 同事务保存；
- 公开读取只访问 `event_publications.is_current`；
- 当前首版支持首次发布；更正、撤回和多独立证据合并仍需后续工作流；
- 生产环境在真实身份系统接入前拒绝工作台和写入端点。

## 5. 明确限制

- 不自动发布真实事件，不替代人工 Reviewer 或 Publisher；
- 不把多个转载计为多个独立信源；
- 不根据单篇内容推断因果、动机或未明确披露的金额；
- 政治、重大金额和争议内容仍服从 R2/R3 的 L2 多人审核门槛。
