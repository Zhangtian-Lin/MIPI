# MVP 需求与验收标准

> 版本：v1.0-draft

## 1. MVP 目标

用 5–10 个稳定来源跑通“采集—版本—抽取—事件—证据—审核—网页”的闭环，覆盖数据中心与 AI 基础设施、半导体、先进制造与新能源，以及四个重点地区。

## 2. Epic

| ID | Epic | 完成定义 |
|---|---|---|
| E01 | 来源接入 | 注册来源可增量采集、限速、失败可追踪 |
| E02 | 文档证据 | 原文、附件、版本、哈希和 source span 可回溯 |
| E03 | 实体事件 | 企业、项目、政策、地区可关联，重复报道归并 |
| E04 | 验证审核 | S/F 等级、冲突和人工审核闭环可用 |
| E05 | Web 浏览 | 首页、变化、实体详情、搜索和证据抽屉可用 |
| E06 | 运维质量 | 构建、监控、备份、恢复和审计具备基线 |

## 3. P0 用户故事

### US-01 今日重要变化

用户可以查看不超过 10 条的重要事件，按产业、州属和事件类型筛选。重复媒体报道不得重复成事件。

验收：每张卡含事件日期、状态、S/F 标签、独立信源数、详情入口；加载、空、冲突和错误状态齐全。

### US-02 项目跟踪

用户可查看项目从意向、宣布、审批、建设到投产的时间线。

验收：当前状态带证据；金额保留原币和口径；延期、暂停、取消可表达；同集团不重复累计。

### US-03 政策版本

用户可查看政策适用对象、条件、生效时间、当前版本和历史版本。

验收：关键字段有 source span；Policy Diff 区分原文变化与平台分析；失效版本不覆盖历史。

### US-04 证据核验

用户从关键事实打开中文、原文和来源。

验收：显示来源类型、发布日期、文档版本、抓取时间和冲突；外链安全打开。

### US-05 搜索

用户可用中文、英文和别名搜索企业、项目、政策、事件和州属。

验收：结果按实体类型分组，说明匹配原因；候选暂存数据不进入公开搜索。

## 4. 数据闭环验收

- 文档写入幂等；
- 原始文件哈希和对象地址存在；
- 关键字段可追溯；
- 同一通讯社转载只计一个 independence group；
- L2 候选不参与公开统计；
- 任何权威数据修改有审计日志；
- 发布必须通过契约校验。

## 5. 非功能基线

- 公开页面生产构建通过；
- API 错误使用统一错误码；
- 核心页面手机、平板、桌面可用；
- 关键流程支持键盘；
- 数据库每日备份并可在测试环境恢复；
- 生产密钥不进入客户端或仓库；
- 网络内容提示注入测试通过。

## 6. 不属于 MVP

全行业覆盖、自动发布政治争议内容、复杂推荐、完整移动 App、无审核的开放式 Agent、对外收费 API 和多人协作均不作为 P0 阻塞项。
